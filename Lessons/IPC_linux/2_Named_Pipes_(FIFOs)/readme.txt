0. Именованные каналы (Named Pipes / FIFO) -> Не гарантируется доставка, 
но гарантируется атомарность записи и чтения если сообщение не больше PIPE_BUF (константа времени компиляции ядра)

	- Создаются с помощью mkfifo() и у них есть имя в файловой системе. Это позволяет общаться любым процессам, даже не связанным родством.

	- Работают через файловую систему, позволяя общаться любым процессам.

Важные моменты:
1. Блокировка при open():

	open(FIFO_PATH, O_RDONLY) блокируется, пока другой процесс не откроет этот FIFO на запись.

	open(FIFO_PATH, O_WRONLY) блокируется, пока другой процесс не откроет этот FIFO на чтение.

	Это синхронизирует соединение сторон.

2. Удаление FIFO:

	FIFO существует в файловой системе, пока его не удалят через unlink().

	Если сервер завершится без удаления, FIFO останется. При следующем запуске mkfifo() вернет EEXIST.

3. Поведение при чтении/записи:

	Если закрыть все дескрипторы записи, читатель получит 0 (EOF).

	Если закрыть все дескрипторы чтения, писатель получит сигнал SIGPIPE (и write() вернет EPIPE).

4. Атомарность:

	В Linux запись в FIFO атомарна для данных размером до PIPE_BUF (обычно 4096 байт). 
	То есть данные от разных писателей не перемешаются, если пакеты меньше этого размера.
