0. Разделяемая память POSIX (shm_open, mmap) с синхронизацией 

	- самый быстрый способ IPC, потому что данные копируются только один раз (при записи) и сразу доступны всем процессам. Но это требует явной синхронизации.

Важные моменты:
1. Синхронизация обязательна — без нее race conditions неизбежны.

2. Именованные семафоры — переживают процессы, удобны для синхронизации между разными процессами.

3. shm_open создает объект в /dev/shm (в памяти, а не на диске):

	bash
	ls -la /dev/shm
	
4. ftruncate устанавливает размер. Если объект уже существовал, данные сохраняются.

5. mmap с MAP_SHARED — изменения видны всем процессам.

6. Семафоры vs мьютексы:

	- Семафоры лучше для подсчета ресурсов (пустые/полные слоты)

	- Мьютексы лучше для простой взаимоисключающей блокировки

7. Очистка обязательна — объекты в /dev/shm живут до перезагрузки или явного удаления.

ВЫВОДЫ:

	- Производительность -> Разделяемая память — самый быстрый IPC: Нет копирования данных между ядром и пользователем (после mmap)

	- Типичная задержка: наносекунды (vs микросекунды для pipe)

	- Пропускная способность: ограничена только скоростью памяти и CPU
	
КЛЮЧЕВОЕ:

	- pthread_mutexattr_setpshared(&attr, PTHREAD_PROCESS_SHARED) — это магия, которая позволяет мьютексу работать между процессами, 
	а не только между потоками одного процесса

	- ftruncate задает размер области памяти под нашу структуру

	- MAP_SHARED — изменения видны всем процессам

	- При первом запуске мьютекс инициализируется, при последующих — используется существующий
