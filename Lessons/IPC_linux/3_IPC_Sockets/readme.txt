0. Unix domain sockets (IPC) -> Гарантированная доставка с и без сохранения границ сообщений (SOCK_DGRAM и SOCK_STREAM соответственно, 
или гибрид: SOCK_SEQPACKET), но в случае останова сервера сообщения теряются (нет очередей)

Важные моменты про UNIX-сокеты:
1. Права доступа: Сокет — это файл в ФС. Можно ставить chmod, как на обычный файл.

2. Автоматическое удаление: При завершении процесса сокетный файл НЕ удаляется автоматически. Нужно делать unlink() вручную.

3. Длина пути: sun_path имеет ограничение (обычно 108 байт на Linux).

4. Производительность: UNIX-сокеты быстрее TCP localhost, так как не проходят через сетевой стек .

5. Двунаправленность: В отличие от pipe, сокеты позволяют обеим сторонам и читать, и писать.

###########################################################################################################################################

Когда данные могут не дойти? Несмотря на "надёжность", есть сценарии, когда данные не будут доставлены:

1. Переполнение буфера (EAGAIN/EWOULDBLOCK)
Если получатель не успевает читать, буфер заполняется. В блокирующем режиме отправитель просто заснёт, но в неблокирующем — получит ошибку :

// Неблокирующий режим
fcntl(fd, F_SETFL, O_NONBLOCK);
ssize_t sent = send(fd, data, size, 0);
if (sent == -1 && errno == EAGAIN) {
    // Буфер заполнен, данные не отправились
}

2. SIGPIPE при чтении
Если получатель закрыл сокет, отправитель получит SIGPIPE (или EPIPE при игнорировании сигнала).

3. EMSGSIZE (для датаграмм)
Если датаграмма превышает лимит (обычно около 200КБ для SOCK_DGRAM), send вернёт ошибку .

4. Обрыв соединения (для стримов)
Если процесс-получатель упал, данные в буфере теряются.

ВЫВОД: 

UNIX-сокеты надёжны настолько, насколько это вообще возможно для IPC:

SOCK_STREAM: надёжный поток байт

SOCK_DGRAM: надёжные датаграммы с сохранением границ

SOCK_SEQPACKET: надёжные датаграммы с установкой соединения
