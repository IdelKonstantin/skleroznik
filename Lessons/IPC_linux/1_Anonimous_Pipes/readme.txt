0. Неименованные каналы (Anonymous Pipes)

	- Создаются с помощью pipe().

	- Используются только между родственными процессами (родитель-потомок).

	Нюанс: В Linux можно создать канал с семантикой датаграмм (флаг O_DIRECT).

Как это работает:

1. pipe(pipefd) создает канал. В pipefd[0] попадает дескриптор для чтения, в pipefd[1] — для записи.

2. fork() создает дочерний процесс. Теперь у нас есть два процесса, и у каждого в памяти лежат свои копии дескрипторов pipefd[0] и pipefd[1].

3. Важно закрывать ненужные концы:

	- Дочерний процесс закрывает pipefd[1], так как он будет только читать.

	- Родительский процесс закрывает pipefd[0], так как он будет только писать.

4. Обмен данными: Родитель пишет в pipefd[1], данные попадают в буфер ядра, и дочерний процесс читает их из pipefd[0].

5. Завершение: Когда родитель закрывает последний дескриптор записи (close(pipefd[1])), дочерний процесс, читая данные, в какой-то момент получит 0 (сигнал EOF), что означает конец потока данных.

0. Неименованные каналы (Anonymous Pipes + O_DIRECT) -> Семантика дейтаграмм

Ключевые отличия от обычного pipe:
1. Создание: Используем pipe2(pipefd, O_DIRECT) вместо pipe(). Флаг _GNU_SOURCE обязателен.

2. Границы сообщений: Каждый write() — отдельная датаграмма. Читатель получит данные именно теми кусками, которыми они были отправлены.

3. Атомарность: Запись в O_DIRECT pipe атомарна до размера буфера канала (обычно 4096 или 65536 байт, можно изменить через fcntl(fd, F_SETPIPE_SZ, size)). Если пакет больше буфера, write() может заблокироваться или вернуть ошибку.

4. Поведение при чтении:

	- Если читатель даст буфер меньше пакета, данные обрезаются? Нет, read() вернет столько, сколько запрошено, а остаток пакета будет потерян? В датаграммных каналах Linux лишние данные отбрасываются, если буфер читателя слишком мал. Будьте осторожны! Проверка на потерянные данные:
